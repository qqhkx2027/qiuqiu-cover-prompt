# 工作流与输出协议

这份文档只处理“什么时候做什么”。视觉参数请读 [style-guide.md](style-guide.md)，跑图时读 [prompt-template.md](prompt-template.md)。

## 输入清单

| 项目 | 必需性 | 处理方式 |
| --- | --- | --- |
| 完整文章 | 必需 | 粘贴正文、提供 Markdown 内容或提供可读取路径；只有标题时标记「待确认」 |
| 真人参考图 | 可选 | 默认使用项目图 1；新图覆盖默认图；无图就不画真人 |
| 真实主体图 | 按文章需要 | 产品、Logo、截图、旅行照等；只索取封面确实需要的图 |
| 旧封面 | 仅编辑模式 | 用于最小范围修改；先确认要改的对象和保留项 |

新图从图 3 开始编号，并在输出中写清楚“这张图用于什么”。不要把默认图 1、图 2 和新增素材混成一个无角色的参考图列表。

## 五个阶段

### 1. 收集

读取文章并确认素材。一次只追问当前阶段缺少的内容：缺文章只问文章，缺必要图片只问图片。

### 2. 分析

从正文记录：

- 一句话主题
- 读者点击理由
- 一个核心数字、结果或冲突
- 必须真实呈现的对象
- 可以从封面删掉的信息

每项都要能在正文中找到依据；找不到就写「待确认」。

### 3. 提案

输出固定结构：

```text
主题判断：...
钩子 A：...
钩子 B：...
钩子 C：...
推荐构图：...
待确认素材：...
```

优先使用结果型、问题型或反差型钩子。用户未确认文案时，不调用图像工具。

### 4. 生成或编辑

用户明确“生成/跑图”后，使用模板生成新图；用户要求局部修改时，只改变点名区域。提示词必须列出参考图角色、准确中文文案、布局和“不添加未授权文字”。

### 5. 验收

至少检查：实际宽高和 2.35:1 比例、正文主题、中文逐字、真人身份、真实素材、Logo、明度、遮挡和是否出现未授权内容。结果不确定时明确写「待确认」，不要把模型输出当作事实。

## 停止条件与恢复

- **缺正文或路径不可读**：停止分析，要求文章。
- **缺必要真实素材**：说明缺哪一张以及可用的文字名/留白替代，等待用户选择。
- **文案未确认**：停在提案阶段。
- **生成失败或验收不通过**：保留已确认文案和提示词，只说明失败项；下一轮仅调整失败项。

## 建议的最终回报

```text
已生成：/absolute/path/to/cover.png
尺寸：1880×800（2.35:1）
文案：...
参考图：图 1=身份，图 2=风格，图 3+=真实主体
已检查：...
待确认：...
```
